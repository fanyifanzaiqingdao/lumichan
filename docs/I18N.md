# 多语言国际化

当前实现位于 dev，支持 English、简体中文、日本語、Español、繁體中文、한국어、Français、Deutsch、Italiano 九种语言。导航、向导申请页、运营后台与客服工作台使用语言菜单，支持键盘上下键、Home、End、Escape。切换语言不重建页面组件，不清空当前表单。

## 网址与语言

| 页面 | 英文 | 中文 |
| --- | --- | --- |
| 首页 | `/` | `/zh/` |
| 服务 | `/traveler/services` | `/zh/traveler/services` |
| 联系 | `/traveler/contact` | `/zh/traveler/contact` |
| 向导申请 | `/guide` | `/zh/guide` |

新增语言前缀为 `/ja/`、`/es/`、`/zh-tw/`、`/ko/`、`/fr/`、`/de/`、`/it/`；其他前台页面沿用相同语言前缀。`/traveler` 和 `/zh/traveler` 是保留查询参数及片段的首页兼容入口，规范地址分别为 `/` 和 `/zh/`。

前台以 URL 语言为准，分享中文网址后接收者也看到中文，不依赖访问者的浏览器语言。语言选择同时保存在 `lumichan-language`，供没有语言前缀的 `/admin` 和 `/support` 使用；这些私有页面不生成语言副本。

`src/i18n/router.jsx` 在原有 React Router 上统一处理 Link、NavLink、Navigate、useLocation，保留原始服务编号、查询参数和锚点。`LanguageProvider` 不改变组件 key，因此切换语言不会丢失输入。

## 后台双语文案

登录 `/admin`，选择“多语言文案”：

1. 搜索英文原文、已有译文或字段名，例如 `homepage.hero.title`。
2. 英文作为基础文案；在“翻译语言”下拉框选择目标语言分别填写。已有译文会预填。切换目标语言保留其他语言的已填内容。
3. 点击“保存双语文案”。前台刷新后读取新内容。
4. 关闭某条覆盖后，恢复内置翻译或源文案。

后台会列出内置文案、当前首页/Services 内容，以及可读取的产品和向导文案。若修改了源文案，应搜索新的原文重新维护对应翻译。相同源文案共享一条翻译，不为同一句原文保存互相冲突的译文。

文件与接口：

- `src/i18n/zh.json`：前台内置中文翻译。
- `src/i18n/en.json`：后台中文源标签对应的英文。
- `src/i18n/{ja,es,zh-TW,ko,fr,de,it}.json`：新增语言的静态翻译初稿，按需加载，不增加英文访问者的七份词库请求。
- `public/api/data/locales.json`：前后端共享的语言、路径、HTML lang 与日期格式配置。
- `src/i18n/runtime.js`：只翻译显示文本，不修改源数据。
- `src/components/TranslationEditor.jsx`：双语编辑、搜索与分页。
- `GET /api/translations.php`：仅返回已启用覆盖，不含后台会话信息。
- `GET/PUT /api/admin-translations.php`：管理员验证、CSRF 校验、字段及大小限制、原子写入。
- `api/data/translations.live.json`：后台保存的运行数据，已忽略 Git 且不进入构建；部署时保留服务器原文件。

没有录入译文的新内容会回退原文。不要在翻译文案中放密钥或客户隐私；启用的显示文案是公开内容。文本通过 React 输出，不作为 HTML 执行。

不要把 `t()` 用于表单 value、业务 ID、价格计算或客户消息正文。中文显示“私人公路旅行”，提交值仍为 `Private Road Trip`。只翻译显示单位，不换算币种、不修改金额与审批记录。

## 客服、错误与后台

首页咨询和联系表单携带当前语言；网站和客服界面支持九种语言，但现有已批准的自动客服知识库仍只有中英文：繁体中文会话使用中文答案，其余新增语言使用英文答案，并在聊天欢迎界面说明。历史会话保持创建时语言，客户和人工消息不自动翻译、不改写。

登录、列表、弹窗、表单、知识库与状态标签支持中英文；账号、联系方式和可编辑业务内容保持原值。已知 API 错误提供翻译，未知内部错误按 HTTP 状态显示通用提示，不将数据库等内部错误原文展示给客户。

## SEO 与发布

`src/i18n/routes.js` 统一语言 URL，`scripts/seo-build.mjs` 在构建时生成：

- 各语言页面对应自身的 canonical；二级页面使用带结尾斜杠的静态入口地址，避免 canonical 指向 Nginx 的目录重定向。
- 相互对应且包含自身的 九种语言与 `x-default` hreflang。
- 九种语言的静态 HTML 入口，JavaScript 执行前已有对应语言、标题、描述和规范地址。
- 正式构建的九语言 sitemap；测试构建无 sitemap，所有语言入口保持 noindex。
- admin/support 的静态 noindex 入口。

页面主体仍由 React 渲染，不是服务端全文渲染。静态 SEO 采用构建时内置内容；后台修改的标题和描述会在加载配置后更新。Google 多语言指导：[Localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions)。

宝塔保持 SPA 回退，并上传构建目录内新增的 `zh/`、`traveler/`、`guide/` 等入口目录。不要只上传 assets。原有规则可继续使用：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

可在正式站 server 块添加旧首页的服务端永久重定向；前端已提供兼容跳转：

```nginx
location = /traveler { return 301 /$is_args$args; }
location = /traveler/ { return 301 /$is_args$args; }
location = /zh/traveler { return 301 /zh/$is_args$args; }
location = /zh/traveler/ { return 301 /zh/$is_args$args; }
```

测试站仍单独添加 `X-Robots-Tag: noindex, nofollow`，不得加到正式站。更新正式包后在 Search Console 重新读取原有 sitemap.xml 即可，无需另建域名资源。

无需数据库迁移，访客侧不新增翻译接口调用；本次离线初稿使用现有 DeepSeek 配置，详见 `docs/LOCALIZATION-REVIEW.md`。本次不修改 main，也不自动推送或部署。
